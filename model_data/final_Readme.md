## 1. PND (Product Needs Document)

### 1-1. 기획 배경 (Why)

| 문제                           | 설명                                                                                                       |
| :----------------------------- | :--------------------------------------------------------------------------------------------------------- |
| **법률 정보의 비대칭성**       | 대기업은 법무팀을 통해 유리한 조항을 삽입하지만, 소규모 계약자는 독소조항을 인지할 전문 지식이 부족합니다. |
| **높은 법률 서비스 문턱**      | 단순 근로계약서 검토를 전문가에게 맡기는 것은 일반 근로자 입장에서 비효율적이고 부담입니다.                |
| **사후 처리가 아닌 사전 방어** | 분쟁 발생 후 소송보다, 계약 전 단계에서 독소조항을 제거하는 것이 가장 경제적인 해결책입니다.               |

### 1-2. 서비스 타겟

- **모든 직장인 근로자**

### 1-3. 핵심 목표

- **협상력 균형 (Equalizer)** — AI를 통해 법적 근거를 확보하여, 계약 상대방에게 조항 수정을 요구할 수 있는 확실한 근거 제공
- **실시간 리스크 진단** — 단 몇 분 만에 계약서 내 숨겨진 리스크를 찾아 의사결정 속도 향상
- **표준 가이드라인 제시** — 문제 지적에 그치지 않고, 법적으로 안전한 '모범 사례'를 제시하여 즉각적인 조항 수정 지원

### 💡 Mission Statement

> **검색의 정확성과 지능을 더해, 법률 전문가가 검토한 것처럼 신뢰성 있는 리포트를 제공한다.**

## 2. 시스템 작동 로직 (시멘틱서치 + RAG)

단순 검색이 아닌 백터 검색과 **RAG (Retrieval-Augmented Generation)** 아키텍처를 통해 신뢰성 있는 법률 분석을 수행합니다.

```
[사용자 입력] ──▶ [독소조항 검출] ──▶ [임베딩 검색] ──▶ [정밀 재순위화] ──▶ [리포트 생성]
  계약서 조항       KoELECTRA-Small      bge-m3 모델        KoELECTRA-Base       LLM 추론
  또는 파일 첨부
```

### Step 1 — 진단 (Input)

사용자 계약서 조항 문구 직접 입력 또는 계약서 문서 파일 첨부

- 파일 첨부 시: LLM이 조항 분류 선행 후 딥러닝 모델에 전달

### Step 2 — 대조 (Search)

**1차 독소조항 검출** (KoELECTRA-Small)

- 학습된 모델이 입력된 조항의 독소 여부 1차 판별

**2차 임베딩 검색** (bge-m3, 기성 모델 그대로 사용)

- 불리 조항: '불공정' 판결이 난 실제 사례 탐색
- 유리 조항: 해당 상황에 가장 적합한 '표준/안전' 문구 확보
- 근로기준법: 해당 독소조항이 위반한 법령 조항 검색

**3차 정밀 재순위화** (KoELECTRA-Base)

- 임베딩 검색 결과를 정밀 심사하여 사용자 조항과 가장 유사한 불리/유리/근로기준법 조항 최종 추출

### Step 3 — 처방 (Reasoning)

LLM이 검색된 '판단 근거'와 '관련 법령'을 종합하여 맞춤형 분석 리포트 생성

## 3. 결과물 구성

사용자에게 제공되는 분석 리포트는 다음 4가지 핵심 요소를 포함합니다.

| 요소            | 내용 설명                                    | 데이터 소스 |
| :-------------- | :------------------------------------------- | :---------: |
| **위험도 등급** | 해당 문구의 위험 수준 평가 (1~5단계)         |  LLM 추론   |
| **위반 근거**   | 조항이 불공정한 이유에 대한 논리적 설명      |  판단근거   |
| **관련 법규**   | 위반 중인 실제 법령 및 조항 명시             |  관련법령   |
| **교정 가이드** | 안전한 표준 문구 제시 및 보완 필요 조항 안내 |  표준조항   |

## 4. 현재 진행 현황

### 데이터 현황 요약

| 구분                         | 수량                    |
| :--------------------------- | :---------------------- |
| 근로기준법 조항 데이터       | 약 400건                |
| 실제 판례 데이터             | 약 2,400건              |
| 독소/표준 학습 데이터셋      | 각 1,500건 (총 3,000건) |
| Cross-Encoder 페어 데이터    | 총 2,800건              |
| 검증 데이터셋(미학습 데이터) | 총 300건                |

---

### ✅ 1단계 — 데이터 확보 및 API 연동 `완료`

**목표:** 근로기준법 위반 여부를 판별할 신뢰성 있는 법률 데이터 확보

**과정:**

- 법제처(국가법령정보센터) API로 근로기준법 관련 판례 수집
- 고용노동부 및 지자체 플랫폼에서 표준근로계약 조항 수집
- 근로기준법 전문 조항 수집

**확보 데이터:** 실제 판례 ~2,400건 / 표준근로계약 조항 ~500건 / 근로기준법 조항 전체

---

### ✅ 2단계 — 데이터 경량화 및 정제 `완료`

**목표:** 학습에 불필요한 노이즈 제거, 모델이 읽기 좋은 핵심 정보만 추출

**과정:** 판례 전문에서 `기초사실`, `인정사실`, `범죄사실` 섹션만 정규표현식으로 추출

**결과:** 원본 대비 **1/10 수준**으로 용량 압축, 사건 맥락 보존

---

### ✅ 3단계 — DB 데이터 구축 `완료`

**목표:** 벡터 검색용 판례 및 근로기준법 조항 데이터 구축

**과정:**

- LLM을 활용하여 판례 원문을 **150자 이내로 요약**
- 근로기준법 조항별 분리 가공

**산출물:** 요약된 실제 판례 데이터 + 조항별로 구분된 근로기준법 데이터

---

### ✅ 4단계 — 독소조항 검출 모델 학습 데이터셋 구축 (1차 필터링 모델) `완료`

**목표:** 판례 내용을 참고하여 실제 근로계약서 조항 문체로 가공

**과정:** 판례 기반 데이터 증강 (무결성 검증: 실제 판례 참고)

**산출물:** 총 3,000건 라벨링 데이터셋

|  레이블   | 구분         | 설명                                                      |
| :-------: | :----------- | :-------------------------------------------------------- |
| `Label 1` | Toxic Clause | 위반 판결 사건을 사측에 유리한 부당 계약 조항으로 변환    |
| `Label 0` | Safe Clause  | 해당 내용을 근로기준법에 부합하는 표준/안전 조항으로 교정 |

---

### ✅ 5단계 — Cross-Encoder 학습 데이터셋 구축 (Re-ranking 단계에서 사용할 모델)

**목표:** 키워드 매칭 오류를 해결하고, 계약 조항과 법령 간 실질적 위반 관계를 0.0~1.0 확률로 판별하는 정밀 심사 모델 구축

**과정:**

| 구성 요소         |  수량   | 방법                                                                    |
| :---------------- | :-----: | :---------------------------------------------------------------------- |
| 골든 정답셋 (1)   | 1,100건 | 검수 판례 100건 + 법령 매칭 1,000건                                     |
| Hard Negative (0) | 1,500건 | `ko-sroberta-multitask`임베딩 모델 로 단어 유사 · 법리 불일치 오답 선별 |
| 논리 함정 (0)     |  200건  | 동일 키워드 내 쟁점 뒤틀기 (예: 임금 조항 ↔ 연차 법령) 오답             |

- **데이터 밸런싱:** 정답 : 오답 = **1 : 1.65**
- **산출물:** 총 2,800건의 `[조항 - 법령 - 라벨]` 페어 데이터셋

**핵심 설계 원칙:**

- **논리적 대조 학습** — 임베딩 모델조차 헷갈렸던 '유사도 오답'을 집중 학습시켜 모델이 단어의 껍데기가 아닌 법리의 알맹이를 비교하도록 유도
- **추론 일관성** — 방대한 법령 전문 대신 실전 계약서와 밀도가 유사한 '100자 내외 법리 요약본' 매칭으로 학습/실전 환경 일치
- **키워드 의존성 타파** — 동일 단어지만 조항 번호·논리가 다른 함정 데이터로 모델의 과적합 방지

---

### ✅ 6단계 — 모델 학습 및 검증

**목표:**

- 5,800건 데이터셋으로 KoELECTRA 미세 조정
  - KoELECTRA(small) : 독소조항 검출 모델
  - KoELECTRA(base) : 정밀 심사 모델
- 별도 검증 데이터를 통해 과적합 여부 진단 및 실전 신뢰도 확보

**계획:**

| 구분           |   수량   | 용도                                 |
| :------------- | :------: | :----------------------------------- |
| Training Set   | ~5,800건 | 모델 학습 주 데이터                  |
| Validation Set |  ~300건  | 성능 평가 및 튜닝 전용 (학습 미참여) |

**검증 방법:**

- Accuracy 및 F1-Score 측정
- '논리 함정' 오답 데이터로 오탐지 집중 테스트
- 임계값(Threshold) 최적화: 결과 분포 분석 후 최적 판정 기준선 도출
  - 예: 유사도 0.88 이상일 때만 독소 조항으로 확정
- 목표 수치 달성 시 최상의 가중치(Best Weights) 모델 시스템 탑재

**목표 수치:**

| 지표                                | 목표         |
| :---------------------------------- | :----------- |
| 검증 데이터셋 Accuracy              | **90% 이상** |
| 논리 함정 오탐지율 (False Positive) | **10% 미만** |

---

### ✅ 7단계 — 부족 데이터 증강 및 재검증

**목표:** 6단계 검증 결과를 기반으로 성능 향상을 위한 부족 케이스 파악 및 보완

**계획:**

- 검증 결과에서 취약 영역 식별 → 타겟 데이터 증강
- 원본 판례 내용을 통한 무결성 검증
- 계약서 특유의 문체로 정제 후 재학습

---

### ✅ 8단계 — 부족 데이터 증강 및 최종 검증

데이터 증강 후 총 7,000건의 데이터셋과 고도화된 학습 기법을 적용한 최종 모델의 성능을 분석한 결과, 실전 배치에 적합한 최상위 수준의 지표를 달성.

### 📈 임계값별 성능 분석 (PR/F1 Curve)

- **F1-Score 최적화:** 임계값 0.54 지점에서 F1-Score가 0.93 으로 정점을 찍으며, 정밀도와 검출률 사이의 가장 안정적인 밸런스를 확보.
- **오탐 방지 역량:** 정밀도(Precision)가 0.95 에 달해, 연관 없는 판례를 잘못 매칭하는 '오탐' 리스크를 최소화.
- **안정적 검출:** 검출률(Recall) 역시 0.91 로 높게 유지되어, 임베딩 모델이 찾아온 유효한 근거 자료들을 놓치지 않고 대부분 포착해 내는 성능을 입증.
