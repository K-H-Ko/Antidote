# 🛡️ 독소조항 1차 분류 모델 개발 과정

모델 학습 목적:
근로계약서 분석 파이프라인의 **첫 관문** 역할을 수행하는 **'독소조항 1차 분류 모델'**의 개발 및 최적화. 후단의 임베딩 모델과 Cross-Encoder가 벡터검색 및 정밀 분석을 수행하기 전, 검토 대상 조항을 빠르고 정확하게 선별.

---

## 1. 파이프라인 및 모델 위치

본 프로젝트의 근로계약서 분석 파이프라인은 다음과 같은 **3단 구조**로 설계되어 있습니다.

```
[입력] 계약서 조항
   │
   ▼
1차 필터: 독소조항 분류 모델 (본 보고서)  ─── 게이트키퍼 (경량/고속, KoELECTRA-small)
   │  → 독소 의심 조항만 통과
   ▼
2차 검색: 임베딩 모델 (벡터 서치)        ─── 후보군 추출 (bge-m3)
   │  → 관련 법령·판례 후보 도출
   ▼
3차 정밀: Cross-Encoder 정밀 매칭 모델     ─── 정답 확정 (RoBERTa-base)
   │
   ▼
[출력] 위반 근거 + LLM 리포트
```

### 🎯 1차 모델의 핵심 요구사항

| 요구사항             | 이유                                                                                                 |
| :------------------- | :--------------------------------------------------------------------------------------------------- |
| **경량성**           | 후단의 RoBERTa Cross-Encoder와 임베딩 모델이 무거우므로 1차는 가벼워야 전체 파이프라인 속도가 보장됨 |
| **높은 Recall**      | 독소를 1차에서 놓치면 2·3차 모델이 작동조차 못함 → **검출률(Recall) 우선**                           |
| **합리적 Precision** | 일부 오탐(FP)은 후단에서 걸러지므로 과도한 정밀도는 불필요                                           |
| **단순 이진 분류**   | 0=표준, 1=독소만 판정 → Cross-Encoder처럼 무거운 구조 불필요                                         |

> **💡 설계 결정:** 1차는 "**수문장**", 후단은 "**판사**" 역할. 수문장이 무거우면 효율이 떨어지고, 너무 까다로우면(precision↑) 진짜 위반자(독소)도 놓침. **재현율 위주의 가벼운 분류기**가 정답.

## 2. 베이스 모델 후보군 비교 검증

1차 게이트키퍼에 적합한 모델을 선정하기 위해, **경량 한국어 인코더 2종**을 후보로 두고 비교 실험을 진행.

> Cross-Encoder 단계에서 검증한 RoBERTa-base는 정밀도가 우수하나 **약 443MB로 1차 필터에는 과중**. 따라서 1차는 별도의 경량 후보군에서 선별.

### 📊 경량 모델 후보 비교 (200개 시드 데이터 기준 기초 검증)

검증 테스트 데이터 셋 1000개 (독소 400 / 표준 500), 3번 테스트 후 평균으로 검증

| 지표            | **KoELECTRA-small (v3)** |   DistilKoBERT   |
| :-------------- | :----------------------: | :--------------: |
| **모델 용량**   |       **약 60MB**        |     약 108MB     |
| **파라미터 수** |         **14M**          |       28M        |
| **추론 속도**   |   **빠름 (~5ms/문장)**   | 보통 (~9ms/문장) |
| **F1-Score**    |        **0.847**         |      0.821       |
| **Recall**      |         **0.86**         |       0.79       |
| **Precision**   |           0.83           |     **0.85**     |
| **특이 사항**   |   짧은 문장 처리 우수    |  긴 문장에 강점  |

### 🔍 KoELECTRA-small 선택 사유

1. **용량 대비 성능 우위**: DistilKoBERT 대비 절반 크기지만 한국어 특화된 모델로 F1 안정적. 게이트키퍼 역할에 최적.
2. **Recall 우위**: 짧은 독소 조항(예: "급여를 명시하지 않는다.") 검출에 강함.
3. **추론 속도**: 실시간 분석 시 4~5ms 차이가 누적되면 큰 차이. 가벼운 만큼 빠름.
4. **확장성**: ELECTRA의 판별(discriminator) 구조가 "이게 정상인가?"를 판별 할 수 있도록 사전학습되어, 정상/이상 이진 분류와 사전학습 목적이 일치.

> **💡 전략적 선택:** `KoELECTRA-small`
> 60MB의 가벼운 몸집으로도 게이트키퍼에 필요한 검출 성능을 충분히 확보. 후단의 Cross-Encoder(443MB)와 결합 시 전체 파이프라인의 속도-정확도 균형이 가장 우수.

- "성과 향상을 위한 자기계발 및 직무 관련 사내 스터디는 자발적 참여를 전제로 운영되므로 기본 근로시간 산정에서 제외함을 인지한다."

**표준(0) 예시:**

- "근로 계약기간은 년 월 일 부터 년 월 일까지 총 개월로 한다."
- "사용자와 근로자는 본 계약서에 서명하여 각각 1부씩 보유한다."
- "근로자는 입사 후 일간의 수습기간을 거치며, 수습기간 중 임금도 통상임금과 동일하게 지급한다."

## 4. 하이브리드 학습 시스템 도입

수작업으로 다양한 독소 패턴을 모두 커버하는 데이터셋을 만드는 것은 비효율적이었습니다. 이에 \*\*LLM(Gemini 3.1 Flash Lite)을 활용한 자율 학습 시스템을 설계하여, 검증시 모델이 자신의 약점을 스스로 진단하고 보완하며 진화하도록 구축.

### 🏗️ 시스템 흐름 (3-Phase)

[PHASE 1] 초기 풀 구축 (1회): Gemini 20회 호출 → 합성 300건 + 기존 3464건 데이터
↓
[PHASE 2] 학습 루프 (반복):
학습 → dev 평가 → 오답 추출 및 패턴 LLM전달 → LLM 약점 공략데이터 생성(학습/오답추출 반복) → Best 갱신 → Early Stopping → 체크포인트
↓
[PHASE 3] 최종 평가 (1회): val_final Threshold 튜닝 → 최종 성능 측정

### 4.1 데이터 분리 격리 (검증셋 오염 차단)

| 데이터셋      |     비중      | 역할                         |   LLM 노출    |
| :------------ | :-----------: | :--------------------------- | :-----------: |
| **train**     | 80% (3,011건) | 가중치 학습                  | 스타일 앵커만 |
| **dev**       |  10% (376건)  | Early stopping + 오답 피드백 |  오답 패턴만  |
| **val_final** |  10% (377건)  | **최종 1회 측정 전용**       | **완전 격리** |

> **💡 핵심:** val_final은 학습 루프 어디에서도 참조 X. Threshold 튜닝조차 학습 종료 후 1회만 수행.

### 4.2 자동 보충 메커니즘 (목표 미달 시)

dev 성능 정체나 특정 유형 오답 누적 시, **30 epoch 주기로 합성 풀 자동 보충**. 단순 추가가 아닌 **약점 정밀 타격** 방식.

30 epoch마다 트리거:

1. dev 오답 추출 → 합성 패턴 / 실제 패턴 분리
2. 카테고리 강제 순환 (독소 8종 × 표준 4종 = 32조합)
3. Gemini가 약점 공략 데이터 생성 (2 calls × 15문제)
4. 이중 중복 차단 후 풀에 추가

### 4.3 과적합 방지 6중 안전장치

|  #  | 장치                                                   | 효과                  |
| :-: | :----------------------------------------------------- | :-------------------- |
|  ①  | val_final 완전 격리                                    | data leakage 차단     |
|  ②  | Best 모델만 보존 (원자적 저장)                         | 종료 시점 ≠ 최종본    |
|  ③  | Early Stopping (patience 15)                           | dev 정체 시 자동 종료 |
|  ④  | 이중 중복 차단 (해시 + Jaccard 0.85)                   | 합성 분포 편향 방지   |
|  ⑤  | 정규화 패키지 (Dropout 0.3, LS 0.1, WD 0.01, Clip 1.0) | 다층 정규화           |
|  ⑥  | 하위 2 레이어 + embeddings 동결                        | 사전학습 지능 보존    |

- 용어설명
  - 해시: 문장 전체를 고유한 코드값으로 변환하여, 토씨 하나 안 틀리고 똑같은 문장을 즉각 찾아내 제거
  - Jaccard 0.85: 단어의 집합을 비교하여 두 문장이 얼마나 유사한지 측정한 값 (85% 유사하면 제거)
  - Dropout 0.3: 학습할 때마다 뉴런(신경망 노드)의 30%를 무작위로 끄고 학습합니다.
    비유: 특정 에이스 뉴런에만 의존하지 않도록, 모든 뉴런이 골고루 협동하여 문제를 풀게 만드는 훈련법입니다.
  - LS 0.1 (Label Smoothing): 정답(Label)을 "100% 독소 조항이야!" 확신 학습이아닌, "90% 정도 독소 조항일 거야"라고 부드럽게 학습시킴.
    비유: 모델이 너무 지나친 자신감을 갖지 않게 하여, 조금 생소한 문장을 봐도 유연하게 대처하게 만듭니다.
  - WD 0.01 (Weight Decay): 모델의 가중치(지능의 파라미터) 값이 너무 커지지 않도록 패널티 부여.
    비유: 복잡한 수식보다 단순한 수식으로 정답을 찾게 유도하여, 억지로 데이터에 끼워 맞추는 것을 방지합니다.
  - Clip 1.0 (Gradient Clipping): 학습 중 오차를 수정하는 힘(Gradient)이 너무 커지면 1.0 수준에서 강제로 잘라냄.
    비유: 모델이 한 번의 학습으로 너무 크게 폭주 하거나, 학습이 망가지는 것을 막아주는 안전장치.

### 4.4 함정 문장 강제 생성

초기 약점("부정형 표준 오탐", "짧은 독소 미탐") 보완을 위해 프롬프트에 강제 규칙 명시:

- **표준 30%↑**: 부정 단어 + "~하지 않는다" 방어형 (예: "수당을 일방적으로 삭감하지 않는다")
- **독소 30%↑**: 공격 단어 없는 조용한 침해형 (예: "행정 업무를 무급으로 이행하여야 한다")
- **독소 20%↑**: 10~25자 짧은 문장 (예: "급여 명세서를 주지 않는다")

### 4.5 학습 하이퍼파라미터

| 카테고리    | 핵심 설정                                                                                    |
| :---------- | :------------------------------------------------------------------------------------------- |
| **모델**    | KoELECTRA-small-v3 / freeze 2 layers / dropout 0.3                                           |
| **학습**    | AdamW(lr=2e-5, wd=0.01) / batch 16 / max_len 256 / grad_clip 1.0 / label_smooth 0.1          |
| **스케줄**  | Linear warmup 200 steps / max 300 epochs / patience 15 / min 20 epochs                       |
| **자동화**  | 초기 풀 20 calls + 기존 풀(3,300건) / refresh 30 epochs / 호출당 15문제 / dup_threshold 0.85 |
| **LLM API** | RPM 15 / RPD 500 / 호출 간 5초 / 429 시 지수 백오프 (30→60→120→300s)                         |

### 4.6 장애 복구 3중화

|  #  | 메커니즘                                | 시나리오 대응                     |
| :-: | :-------------------------------------- | :-------------------------------- |
|  ①  | 매 epoch 원자적 체크포인트 (tmp→rename) | 부분 쓰기 / 디스크 오류           |
|  ②  | 루프 내부 try/except (OOM 별도 처리)    | 한 epoch 실패해도 다음 epoch 진행 |
|  ③  | SIGTERM 핸들러 + finally 저장           | Colab 세션 끊김 / 강제 종료       |

→ 재실행 시 progress.json + synthetic_pool.json + best/ 자동 복원으로 **수일에 걸친 학습도 안전 보장**.

> **💡 설계 철학:** 학습 모델의 오답 패턴을 LLM에게 피드백 → LLM이 약점 공략 데이터 생성 **자가 진화 루프**. 검증 데이터는 LLM에 절대 노출되지 않게하여 동일한 문제 생성 차단, 6중 과적합 방지 + 3중 복구 체계로 학습 안정성과 일반화 능력을 동시 확보.

## 5. 학습 진화 과정

자율 학습 시스템을 가동하며 발견된 문제와 해결 과정을 기록합니다.

### 🔄 1. 합성 데이터 과적합

- **현상:** dev_f1 1.0 달성, 하지만 val_final F1 0.65
- **원인:** Gemini가 생성한 합성 데이터에 dev 분포가 유출 → dev에서만 완벽
- **조치:** dev에 실제 검증 데이터 일부 편입, val_final 완전 격리 강화

### 🔄 2.키워드 매칭 편향

- **현상:** "삭감/차감/공제" 등 부정 키워드 = 독소로 단순 매칭, 부정형 표준("~하지 않는다")을 모두 독소로 오판
- **원인:** 합성 데이터에 부정형 표준 샘플 부족
- **조치:** 프롬프트에 **"함정 문장 강제 생성"** 규칙 추가 → 표준 30%는 부정어 포함 방어 문장으로 강제

### 🔄 3. 짧은 독소 미탐

- **현상:** "급여를 주지 않는다." 같은 단순 독소를 놓침
- **원인:** 시드 데이터의 평균 문장 길이가 59자로, 짧은 표현 학습 부족
- **조치:** 프롬프트에 **"독소의 20%는 10~25자 짧은 문장"** 강제 규칙 추가, 데이터 길이 필터 완화

### 🔄 4. 데이터 통합

- **3,464건 + 자동생성 300건 을 학습 데이터에 통합** → 총 3,764건 학습 풀
- **8:1:1 분할** (train 3,011 / dev 376 / val_final 377)
- 클래스 가중치 제거 (균형 데이터에서 불필요), Threshold 튜닝으로 Recall 제어

## 7. 결론 및 향후 전망

본 프로젝트를 통해 개발된 1차 독소조항 분류 모델은 **60MB의 경량 구조로 Recall 93%**를 달성하며, 계약서 분석 파이프라인의 첫 관문 역할을 안정적으로 수행할 준비를 갖추었습니다.

1. **파이프라인 효율성 확보:** 1차에서 빠르게 의심 조항을 선별하여 무거운 후단 모델(임베딩 + Cross-Encoder)의 호출량을 약 60% 절감. 전체 파이프라인 응답 속도 개선.

2. **놓침 최소화 전략:** Threshold 0.45 튜닝을 통해 Recall을 0.94까지 끌어올림으로써, "위반 조항을 사용자에게 안내하지 못하는 최악의 시나리오"를 원천 차단.

3. **자율 학습 인프라 자산화:** Gemini 기반 자동 데이터 증강 시스템은 본 모델 외에도 향후 분야 확장시 동일한 방식으로 재활용 가능한 **재사용 가능한 학습 인프라**로 변형 가능.

4. **지속적 고도화:** 실전 운영 중 수집되는 신규 오탐/미탐 사례를 자동화 시스템의 dev 풀에 주기적으로 편입하여, 모델이 실제 사용자 패턴을 흡수하며 점진적으로 진화하도록 운영 전략 수립.
